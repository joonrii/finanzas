# UX & Design

## Design goal
La app debe sentirse premium, moderna, sencilla y rápida.

La estética es una parte central de la propuesta de valor, no un añadido posterior.

## Design principles
- Una pantalla debe tener una jerarquía visual clara.
- Pocas acciones por pantalla.
- Mucho espacio y buena legibilidad.
- Animaciones sutiles que aporten feedback y sensación de calidad.
- Los datos financieros deben ser fáciles de escanear.
- El usuario no debe sentirse frente a una hoja de cálculo.
- Los logos de comercios deben utilizarse cuando sea posible y útil.

## Core screens
### Inicio
Debe responder inmediatamente:
- Cuánto tengo.
- Dónde está.
- Cuánto he gastado este mes.
- Cómo evoluciona mi patrimonio.

### Movimientos
Lista visual de gastos e ingresos.

Cada movimiento puede mostrar:
- merchant/logo
- nombre
- categoría
- fecha
- cuenta
- importe

### Analizar
Debe responder principalmente:
- En qué gasto.
- Cómo ha cambiado respecto a otros periodos.
- Cuál es la distribución de mis gastos.

### Añadir movimiento
Prioridad máxima de velocidad y simplicidad.

## Mobile-first
Aunque exista una webapp, el diseño debe anticipar la futura aplicación iOS.

La experiencia móvil es prioritaria.

## Internationalization
Diseñar desde el principio para:
- English — prioridad #1
- Spanish — prioridad alta
- French — prioridad alta
- Italian — prioridad alta
- German — prioridad alta
- otros idiomas posteriormente

La arquitectura debe soportar:
- monedas
- formatos de fecha
- formatos numéricos
- traducciones
- categorías localizables

## Future iOS UX
La app iOS podrá añadir:
- Shortcuts.
- Widgets.
- Quick actions.
- Integración con el sistema cuando sea técnicamente viable.

No diseñar estas funcionalidades todavía como parte del MVP web.
